Fixed a `SIGSEGV` on Android when the FFI layer is loaded into a React Native
process. AWS-LC (pulled in by `rustls-aws-lc-rs`) declares `sdallocx` as a weak
function and calls it whenever it resolves to something non-NULL. React
Native's `libreactnative.so` and `libjsi.so` export `sdallocx` as a *data*
object, so the dynamic linker bound that reference to the address of a
variable, and the first call branched into a non-executable page.

Android builds now link a hidden-visibility definition of `sdallocx` that
simply forwards to `free`, which is what AWS-LC does when the symbol is absent.
The definition is non-preemptible, so it is bound at static-link time and the
colliding symbols are never consulted.
