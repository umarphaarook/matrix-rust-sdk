[**breaking**] `DecryptionSettings` has a new public field, `refuse_legacy_from_unsigned_known_devices` (off by default), so struct literals must set it. With it on, and under `TrustRequirement::CrossSignedOrLegacy`, a legacy session (for instance one imported from a key backup) is refused with `SenderIdentityNotTrusted(UnsignedDevice)` when its sender key belongs to a device of the claimed sender that we currently know and that is not cross-signed by its owner, as a live session from that device would be. This closes a way for a backup restore to decrypt, on a new device, messages that the receiving device had refused. It is best effort and covers the honest-device case only: it does not defend against a homeserver that withholds the device, and the result depends on the order in which we learn about the device and decrypt (an event already decrypted and cached, or decrypted before the device was known, is not revisited). Authenticated sender data in the backup (MSC4048) is the real fix. A legacy session whose sender device is unknown or cross-signed keeps decrypting, and the refusal is lifted when the device becomes cross-signed.
